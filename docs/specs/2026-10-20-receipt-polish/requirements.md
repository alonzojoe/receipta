# Receipt document polish

## Goal

Three changes to the generated receipt, from the author after looking at a real export:

> "below the Generated by Receipta put the purple icon near the Receipta img, and on the
> header remove the logo in there, then make the purple line same as color with the
> current lines in the receipt"

So: the mark moves from the header to the footer, beside the wordmark, and the violet rule
under the title becomes the same colour as every other line in the document.

Nothing else about the receipt changes. The layout, the type scale, the pagination, the
export pipeline and the money rules are all untouched.

## Decisions

| Decision | Choice | Why |
| --- | --- | --- |
| The mark's position | **Footer only**, immediately beside the wordmark | One brand mark in one place. It was in both the header and the footer, which read as two logos on a one-page document. The footer is where the credit already lives, so the mark joins the thing it belongs to rather than floating at the top. |
| The title rule's colour | **`--receipt-rule`**, the same hairline grey as every other rule | The author's instruction. It also removes the only place where a structural line carried brand colour, which is what made it read as decoration rather than structure. |
| The title rule's weight | **Unchanged at 2px** | The instruction was about colour. The title rule is still the heaviest in the document, which is what separates the title block from the metadata, and it keeps that job in grey. |
| What stays violet | **The mark, and the "Amount paid" figure** | Two touches, down from three. The mark is violet by being the logo, not by a rule. The figure is the one number a reader is looking for. |
| The mark's size in the footer | Sized to the wordmark's optical height, not the header's 28px | A 28px mark beside a 16px wordmark would dominate the credit it belongs to. |

## Scope

In scope: `receipt_blocks.tsx` (the title row and the footer), `receipt_document.css`, and
the tests that pin the mark's position and the accent's selectors.

Out of scope: the app's own navbar logo, the `--receipt-*` palette values themselves, the
type scale, pagination, and anything in `features/receipt_export`.

## Acceptance criteria

1. The title row contains no image. The document's first page opens with the word
   "Receipt" and nothing beside it.
2. The footer shows, in order: the "Generated by" label, the Receipta mark, and the light
   wordmark. The mark sits immediately beside the wordmark as one unit, not at the far
   side of the footer.
3. The mark and the wordmark are optically balanced and read as one lockup rather than
   two images. The mark is **20px against the wordmark's 16px** — amended from "no greater
   than the wordmark" on the author's instruction to make it bigger. Taller is correct
   here: the mark is a compact shape and the wordmark is lowercase text, so matching their
   box heights makes the mark read smaller than it measures.
4. The rule under the title resolves to `--receipt-rule`, the same value as every other
   rule in the document, verified from the stylesheet rather than by eye.
5. `--receipt-accent` is used in exactly one place in the document stylesheet: the
   "Amount paid" figure. A test pins the list of selectors that use it.
6. The footer still carries `Page N of M` on multi-page PDFs, and the page label is not
   displaced by the mark.
7. The white-paper guarantee is unaffected: no `dark:` variant, no theme token, and the
   reset still covers every property it covered before.
8. Both logo images still carry `data-logo="receipta"`, so the asset-wait before
   rasterising still finds them. **This is the one that silently breaks an export**: the
   rasteriser waits on those images, and a mark that moves without its attribute would
   either not be waited for or not be found.
9. The footer's measured height is whatever it now is — the pagination measures at
   runtime, so no constant needs updating, but a test confirms the footer unit is still
   measured as one block.
10. `npm run build`, `npm run lint` and `npm test` exit 0.

## Verification

Chrome automation is not available for this change (author instruction), so:

- Criteria 1, 2, 4, 5, 7 and 8 are verified by tests over the rendered DOM and the
  stylesheet source.
- Criterion 3 is a judgement about optical balance that cannot be measured in jsdom. The
  sizes are chosen from the known intrinsic dimensions of the two assets and stated in the
  validation doc as **not visually confirmed**, for the author to check on screen.
- The light-versus-dark pixel diff is **not re-run**. The source-level reset test still
  passes, and no new colour property is introduced, but the pixel comparison that was run
  for the export work is not repeated here.

## Deferred

- Whether the "Amount paid" figure should stay violet now that it is the only coloured
  text in the document. It may read as arbitrary without the title rule to pair with.
- Whether the title rule should drop to 1px now that it is grey, making every rule in the
  document identical. Kept at 2px because it still separates the title block.
